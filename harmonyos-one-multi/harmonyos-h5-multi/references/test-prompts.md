# Skill 测试提示词

修改 description、输入模式、路由、禁止模式或资源索引后运行这些用例。检查模式判定、可编辑层、完成声明和最少资源读取。

## 应触发

以下用例都先执行 `H5-00` 前置审计；`H5-00` 不计入主次场景。

1. “修改这个 HTML/CSS 新闻首页，让它适配展开横屏。”期望 `H5_ONLY`，主场景 `H5-02`（宽屏结构）；只有存在宽而短导致的首屏不可操作时，才加次场景 `H5-03`。只改 Web。
2. “Vue 卡片在平板分屏时横向溢出。”期望 `H5_ONLY`，主场景 `H5-01`；仅在问题确实涉及动态切换时添加 `H5-05`。
3. “外屏打开字体小，展开后仍小；页面使用动态 REM，clientWidth 已变化但 html font-size 没变。”期望 `H5_ONLY`，主场景 `H5-07`；按既有有界公式重算根字号。
4. “只有 ArkTS Web 组件和窗口监听代码，请把变化通知网页。”期望 `ARKTS_ONLY`，主场景 `H5-08`；只改原生生产端，输出 H5 交接项，不声称端到端完成。
5. “这里有 ArkTS 的 onScreenChange 和 H5 的 REM 初始化，请联动修复。”期望 `HYBRID`，主场景按首个错误约束选择 `H5-08` 或 `H5-07`，另一项仅在独立相关时列为次场景。
6. “H5 已监听原生事件，但源码里没有 ArkTS。”期望 `H5_ONLY`，主场景 `H5-08`；可修消费端，明确原生生产端不可验证。
7. “ArkTS 每次旋转 reload Web 页面，H5 也提供了。”期望 `HYBRID`，主场景 `H5-08`；用稳定信号和 H5 响应式更新替换 reload，双端验证状态。
8. “container query 在最低支持浏览器不生效。”期望 `H5_ONLY`，主场景 `H5-06`。
9. “新闻卡片在外屏下载 2000px 大图，展开后图片反而模糊。”期望 `H5_ONLY`，主场景 `H5-09`；检查 slot、候选固有宽度、`srcset/sizes` 和 `currentSrc`。
10. “展开横屏需要横版头图，折叠外屏需要突出人物的竖版裁切。”期望 `H5_ONLY`，主场景 `H5-09`，次场景 `H5-03`；使用 `<picture>` 表达 art direction，不用 JS 判断机型。
11. “视频在折叠后被拉伸，每次旋转代码都会重新 load。”期望 `H5_ONLY`，主场景 `H5-09`；仅在 resize 更新链本身异常时添加 `H5-05`。
12. “根字号已经从 80px 更新到 96px，但 1200px 宽屏页面靠左、仍是单列且右侧留白。”期望 `H5_ONLY`，主场景 `H5-02`；检查内容壳、导航和宽屏结构，不继续提高 REM 上限。
13. “flexible 的 maxWidth 是 540，目标折叠屏宽 1010，直接帮我把上限改成 1010。”期望 `H5_ONLY`，主场景 `H5-07`；先审计设计基准、构建转换、字号/图片结果和内容断裂点；不按设备宽度直接修改上限。
14. “750 设计稿、remUnit=75、缩放上限 540，请检查源码 750px、生成的 10rem 和运行时宽度是否一致。”期望 `H5_ONLY`，主场景 `H5-07`；建立 `D/R/V/C` 模型，同时检查 PostCSS 配置和生成 CSS。
15. “新写一个同时适配手机、平板和折叠屏的 H5，全部尺寸用动态 REM。”期望 `H5_ONLY`，主场景 `H5-02`；不默认引入动态根字号，不读取 `rem-responsive.md` 的修复流程；使用 Grid/Flex、内容断点、container query 和有界流式 token。
16. “页面顶部被状态栏挡住，`env(safe-area-inset-top)` 打印出来是 0。”期望先确认容器沉浸方式与 `viewport-fit`；只有 H5 时主场景 `H5-04`，把容器配置列为交接项或待确认项，不宣告完成。
17. “输入框聚焦后底部操作栏被键盘盖住，ArkTS 和 H5 都提供了。”期望 `HYBRID`，主场景 `H5-04`，次场景 `H5-08`；先确认 `setKeyboardAvoidMode` 与 Web `keyboardAvoidMode`，再选择匹配的 H5 偏移方案。
18. “只有 ArkTS 页面，Web 组件写死 `height(800)`，折叠后网页下半截空白。”期望 `ARKTS_ONLY`，主场景 `H5-08`；修复外部尺寸链即可闭环，说明 H5 无需改动的证据。
19. “分屏拖动后列表滚动位置和已填表单丢了。”期望主场景 `H5-05`；检查条件渲染是否销毁状态，不用 reload 或设备分支。
20. “页面用动态 REM，我加了 `@container (min-width: 32rem)`，组件一直不切换。”期望 `H5_ONLY`，主场景 `H5-01`（根字号符合公式，问题在组件阈值单位，不选 `H5-07`）；识别 `rem` 在 container query 中按动态根字号解析，阈值在生成 CSS 中改用 `px`。
21. “Vue 工程用 flexible.js + postcss-pxtorem（`propList: ['*']`），我把侧栏写成 `width: 256px`，宽屏下侧栏还是跟着变大。”期望 `H5_ONLY`，主场景 `H5-02`（根字号正常，问题是结构尺寸被插件转换，不选 `H5-07`）；先读取 PostCSS 配置和生成 CSS，识别源码 `px` 已被转成 `rem`；用 `selectorBlackList`/`exclude` 或大写 `PX` 保留，并核对产物。
22. “工程用 postcss-px2rem，加了 `@container` 之后构建报错。”期望 `H5_ONLY`，主场景 `H5-01`；识别 px2rem 的旧解析器不支持 `@container`；把容器查询样式放进不经过 px2rem 的文件，或改用 media query。
23. “平板分栏后，读屏先读右侧详情再读左侧列表。”期望 `H5_ONLY`，主场景 `H5-02`；找出只在宽屏断点生效的 `order`/`grid-area`/`*-reverse`，让 DOM 顺序与逻辑顺序一致，不用正数 `tabindex` 或 `aria-flowto` 修补；说明屏幕朗读需要真机验证。
24. “窄屏底部导航只有图标，读屏只读出‘按钮’。”期望 `H5_ONLY`，主场景 `H5-02`；保留文字并在窄屏视觉隐藏，或给控件加描述目的的 `aria-label`，图标加 `aria-hidden`；iconfont 伪元素不能作为名称。
25. “宽屏把订单列表改成多列表格后，每行的文字操作收成了删除图标，读屏全是‘删除’。”期望 `H5_ONLY`，主场景 `H5-02`，读取 `a11y-reflow.md`；给每个按钮带上行上下文（`aria-label` 或 `aria-labelledby`），不只加同一个名称。
26. “视频页全屏时横屏，退出全屏再退出页面后，其他页面仍是横屏。ArkTS 和 H5 都提供了。”期望 `HYBRID`，主场景 `H5-08`；列出全部方向调用方，补齐请求与释放配对和页面生命周期释放，恢复到加锁前方向而不是写死竖屏。
27. “只有 H5，页面进入时通过桥接请求横屏。”期望 `H5_ONLY`，主场景 `H5-08`；在路由离开、`pagehide` 和退出全屏时发释放，原生方向管理器和生命周期挂载列为交接项，不在 H5 侧虚构原生 API。
28. “H5 页面用 Grid 布局，折叠屏展开后卡片没铺满，右侧留白。”期望 `H5_ONLY`，主场景 `H5-02`；先确认网格容器宽度是否已随窗口变化，再检查固定轨道宽度、`auto-fill` 空列、写死列数和 JS 首次计算，先判定卡片属于弹性卡片，改为 `minmax(…, 1fr)` 让列宽伸缩；动态 REM 工程中最小列宽在生成 CSS 中保持 `px`。
29. “头像修改页提供默认头像，手机上 Grid 3 行 6 列，折叠屏和平板上右侧留白。”期望 `H5_ONLY`，主场景 `H5-02`；先识别头像是固定尺寸小元素，保持头像尺寸不变，轨道改 `repeat(auto-fill, minmax(尺寸, 1fr))` 加 `justify-items: center`，宽屏可给网格设上限并居中；不得把头像拉伸到填满轨道；需要整行时在断点内指定列数。
30. “H5 写邮件弹框里有收件人、主题和正文，聚焦正文后键盘盖住了发送按钮；容器是 `RESIZE_VISUAL`。”期望 `H5_ONLY`，主场景 `H5-04`；识别为弹框内输入并选方案 A：遮罩按 `visualViewport` 的 `offsetTop/height` 定位，头部和底部固定、只有中间区滚动，焦点字段在中间区内露出；不让整个弹框滚动，不调用 `window.scrollTo`。
31. “只有一个验证码输入框的居中弹框，键盘弹出后下半截被盖住。”期望 `H5_ONLY`，主场景 `H5-04`；识别为内容放得下的弹框，选方案 B：不新增内部滚动，用 `visualViewport` 把弹框放进键盘上方的可见区，保留中间区滚动兜底；若容器是 `OVERLAYS_CONTENT`，列交接项而不是宣告完成。
32. “沉浸式 H5 登录页，聚焦输入框后标题跑到状态栏下面；网页打印的 `scrollY` 和 `visualViewport.offsetTop` 都是 0，`innerHeight` 也没变。只有 H5。”期望 `H5_ONLY`，主场景 `H5-04`；按判别表认定是容器上推，H5 侧的补偿无效；把页面级避让改为 Resize、Web 用 `RESIZE_CONTENT` 列为交接项，不宣告完成。
33. “登录页有标题、副标题、两个输入框和登录按钮，键盘弹出后按钮被挡住，聚焦时我们用 `setTimeout` 把按钮 `scrollIntoView` 到底部，结果标题进了状态栏；容器是页面级 Resize 加 `RESIZE_CONTENT`，ArkTS 和 H5 都提供了。”期望 `HYBRID`，主场景 `H5-04`；判定为网页滚动，去掉固定延时滚动，用文档流布局、按钮紧跟表单和 `form` 回车提交，键盘弹出时压缩顶部，按“最小必要滚动与上限”做校准，并加状态栏遮罩兜底；`env()` 为 0 时由 ArkTS 注入 `--native-safe-top`。
34. “沉浸式容器里的多字段表单弹框，键盘弹出后弹框头部被状态栏盖住。”期望 `H5_ONLY`，主场景 `H5-04`；先排除容器上推，再让遮罩的内边距消费 `--safe-*`，并保留方案 A 的三段式结构。
35. “存量移动页面加了整页限宽居中，宽屏下弹层里的确认按钮超出弹层；按钮宽度写的是 `90vw`。”期望 `H5_ONLY`，主场景 `H5-02`；识别视口基准与容器基准分裂，改用 `%` 或 `cqi`；检索限宽层内其他 `vw`、`position: fixed`、`@media` 写法，不只修报出的按钮；在宽于上限的视口下量测按钮位于弹层内，不能渲染时写明未验证。
36. “整页限宽后，一个以整幅视觉为主的页面在宽屏下整体偏右，它的根容器写的是 `width: 100vw`。”期望 `H5_ONLY`，主场景 `H5-02`；先确认页面意图是通栏还是跟随容器，不默认改成 `100%`；需要通栏时使用通栏突破写法，并检查横向滚动。
37. “整页限宽到手机宽度后，宽屏视口下容器里出现了双栏布局并被挤压变形。”期望 `H5_ONLY`，主场景 `H5-02`；识别 `@media` 以视口为参照，限宽容器内的组件改用 `@container`。
38. “Vue 工程用 postcss-pxtorem，`rootValue` 按 750 设计稿配置；引入组件库后，按钮和弹层都只有设计稿的一半大小。”期望 `H5_ONLY`，主场景 `H5-07`；识别组件库的设计基准与项目不同，`rootValue` 改为按文件路径返回不同值，或排除组件库后单独配置；不修改组件库源码。
39. “存量移动工程要在宽屏下整页限宽居中，问是否要把所有 `vw` 手工改成 `%`。”期望 `H5_ONLY`，主场景 `H5-02`；先判断能否用构建期限宽方案统一处理，再按参照基准表核对插件覆盖不到的内联样式、JS 尺寸、`sizes` 和组件库弹层；不要在已启用构建期限宽时再手改同类写法。

## 不应处理

1. “修改普通 ArkTS GridRow 页面，里面没有 Web 组件或 H5。”不属于本 skill 的 Web 多设备适配。
2. “折叠后相机预览黑屏。”不属于 H5 布局或 Web 容器桥接。
3. “实现跨设备接续和数据流转。”不属于响应式布局。
4. “优化普通网站 API 请求速度。”与多设备响应式无关。
5. “这个 H5 设置页的图标按钮没有 aria-label，手机上读屏只读‘按钮’，没有做过任何断点或分栏。”任何窗口下都存在的普通无障碍缺陷，不属于本 skill。

## 边界用例

1. 同时出现 `.ts` 与 `.ets`：普通 `.ts` 不因项目含 HarmonyOS 就自动算 ArkTS；按导入、语法和目录判定。
2. 只给截图和日志：期望 `INSUFFICIENT`，列所需源码，不生成未经验证补丁。
3. 双端都提供但根因是 CSS `min-width`：期望 `HYBRID`；修改 H5，说明 ArkTS 契约检查无影响，不强造原生改动。
4. 双端事件字段重命名：生产者、消费者、类型和测试必须原子更新。
5. 原生传窗口宽度（如 vp 数值）：允许作元数据，但 H5 REM 最终读取 `clientWidth`。
6. H5 使用 `addEventListener('resize', refreshRem())`：识别函数调用结果问题。
7. 用户指定具体机型：仅用于复现矩阵，布局代码不得按机型或 UA 分支。
8. `srcset` 使用 `w` 描述符但没有 `sizes`：不能默认候选选择正确；先从 computed layout 得到真实 slot。
9. 窗口由宽变窄后 `currentSrc` 仍是大图：浏览器可能复用已加载资源；只要清晰度、布局和后续首次加载选择正确，不强制降级重载。
10. CSS 背景图承载新闻标题所需信息：改为语义 `<img>`/`picture` 和有效 `alt`，不能只增加 `image-set()`。
11. `initial-scale=1` 且设备 DPR 为 3：不得把 viewport scale、`window.devicePixelRatio` 与 flexible 内部 `dpr` 混为一谈。
12. px→rem 插件转换了结构性 `max-width` 或媒体查询阈值：必须查看生成 CSS，不能按源码字面值推导运行时尺寸；“改用 px”的建议必须带上对该插件有效的保留写法。

## 评分点

- 首先输出 `input_mode`，并用文件或调用链证明。
- `H5-00` 只作为前置审计；`primary_scene` 必须表示实际根因。
- 单端模式不越界修改，`missing_counterpart`/`handoff_required` 清楚且可执行。
- `HYBRID` 沿系统事件到 DOM 更新检查完整链路；契约变化同步两端。
- H5 负责 viewport、CSS、DOM 和 REM；ArkTS 负责系统语义、Web 生命周期与桥接。
- 不把原生 dp、物理屏幕或型号直接当 H5 布局输入。
- 不用 reload 代替响应式更新；监听可释放、更新幂等且保留业务状态。
- 动态 REM 被视为有界的存量兼容层；根字号正常时不靠提高上限解决宽屏结构问题。
- 能从设计宽度、构建 rootValue、当前 viewport 和缩放上限推导运行时尺寸，并核对生成 CSS。
- 宽屏新增空间由重复、挪移、缩进或分栏布局利用，字体和图片不随 viewport 无界整体放大。
- 直板机基线、临界值、外屏↔内屏、旋转和首次状态完成回归。
- 安全区与键盘问题先确认 ArkWeb 容器配置，再改 CSS/JS。
- 弹框内输入被键盘遮挡时先识别为弹框场景并按内容高度选方案；头部和底部固定、仅中间区滚动，弹框整体位于可见区域内，沉浸式下遮罩消费安全区。
- 键盘相关问题先判别是容器上推、双层避让叠加还是网页滚动；前两种列交接项，不在 H5 侧补偿。
- 整页表单先压缩顶部，再做有上限的最小必要滚动；焦点输入框 > 主按钮 > 标题，状态栏遮罩只作兜底；不用固定延时 `scrollIntoView`，也不补键盘高度的占位。
- 重排后的读屏和焦点顺序按 DOM 顺序修复，逐断点验证；仅图标控件有描述目的的名称，装饰图标隐藏；不把未经真机验证的屏幕朗读结果写成已通过。
- 动态 REM 页面中的结构断点、container query 阈值、栏宽和 `sizes` 在生成 CSS 中是 `px`；有转换插件时给出插件实际支持的保留写法。
- 整页限宽时区分视口基准与容器基准，检索同类写法而不只修报出的元素；页面意图不明时先确认，不默认改写原有视觉。
- 涉及宽度、定位或单位的改动有渲染量测证据，或明确写“未做渲染验证”。
- 媒体策略能区分流式缩放、resolution switching、art direction 和装饰背景；`sizes` 描述 slot 而非物理屏幕。
